> 상태: 분석 → 설계 단계. 구현은 아직 시작하지 않았고, `app.py` 등 기존 코드는 **첫 초안**이라 M0에서 이 설계에 맞게 교체합니다.

표기: ✅ 스크린샷으로 직접 확인 / 🔶 추정(근거는 있으나 확정 아님) / ❓ 미확인

## 1. 목표와 범위

**목표**: 외부 블로그 원고 생성 서비스(이하 "원본")의 *FREE 플랜* 동작을 보고, 비슷하게 동작하는 개인용 도구를 만든다. 원본의 코드·프롬프트는 알 수 없으므로 "동일"이 아니라 "관찰된 동작을 재현"하는 것이 목표다. 그다음 *BASIC 플랜* 차이를 설정으로 추가한다.

**포함**
- 원고 작성 화면 (글 종류, 매장 검색, 사진 업로드, 제목 자동 생성, 원고 생성)
- 결과 화면 (글자수, 글꼴, 글자 크기, 색연필, 복사, 새 원고)
- 내 원고 (목록, 상세, 복사, 삭제)
- 사진 분석, 썸네일, 해시태그, 네이버 블로그 붙여넣기용 복사

**제외 (사용자 결정)**
- 로그인, 요금제, 일일·월 한도, 한도 소진 화면
- 자동발행(네이버 블로그 발행 대행), 비즈니스(BUSINESS) 플랜, 전담 매니저
- 내 사진 라이브러리, 사용한 사진 자동 제외

**단계**: FREE 재현 → BASIC(모델, 사진 6장, 썸네일 4종, 글 종류 전체) 추가.

## 2. 원본 관찰 요약 (설계의 근거)

### 2.1 화면
| 항목 | 내용 | 표기 |
|---|---|---|
| 글 종류 | 정보글, 맛집글, 전문직, 홍보글, 커스텀, 기타 (일부 ❓ 툴팁) | ✅ |
| 맛집글 흐름 | 매장 이름 → [자동 입력] → 후보 카드(업종·주소) 선택 → 요약줄(`상호 (업종) 주소 \| 전화`) | ✅ |
| 사진 | [사진 업로드] [폴더로 업로드]. 올리면 `사진 N장 분석 완료` 한 줄만 표시(썸네일·순서 변경 없음) | ✅ |
| 제목 | 직접 입력 또는 [제목 자동 생성] → 후보 5개, 클릭하면 제목 칸이 바뀜. 후보 아래에 `✓ 매장: … · 메뉴 5개`처럼 사용한 정보 표시 | ✅ |
| 원고 생성 | 제목 입력 후 별도 [원고 생성하기] 버튼 | ✅ |
| 단축키 | 제목 재생성 `R`, 복사 `C`, 새 원고 `N` | ✅ |
| 결과 | 글자수 `N / 2800`(공백 제외·해시태그 제외 기준, §2.8), 사진 N장, 글꼴(나눔고딕·맑은고딕·본고딕), 크기(13~17px, 기본 15), 색연필(최대 4색, 색 직접 추가) | ✅ |
| 내 원고 | 누적 원고 수, 목록(제목·글 종류 배지·일시), 제목 클릭 → 상세(복사), `×`와 `선택 삭제` | ✅ |
| 썸네일 ON/OFF 스위치 위치 | 화면에서 찾지 못함 | ❓ |
| 결과 본문 직접 수정 가능 여부 | | ❓ |

### 2.2 원고 구조 (맛집글 2건 비교: 락희옥 / 김숙성)
- 틀은 고정: **제목 → 인트로 2~3문단 → 1. 위치·분위기 → 2. 주문한 메뉴 → 3. 다른 메뉴·추천 조합 → 4. 다시 갈 만한가? → 해시태그** ✅
- 섹션당 3~5문단(락희옥 4·4·3·4, 김숙성 3·5·4·4, 인트로 3 / 2), 문단은 2~3문장, 1인칭 후기 문체("저는…", ~더라고요 / ~습니다 혼용) ✅
- 소제목 문구는 매번 달라짐("위치와 분위기" ↔ "위치 & 분위기") → 틀은 고정, 문구는 AI 작성 ✅
- 1번 섹션 끝에 `(플레이스 지도 삽입: 〈상호〉)` 한 줄 (네이버 에디터의 [장소] 버튼으로 직접 넣는 자리표시) ✅🔶
- 공백 제외·해시태그 제외 약 2,040~2,100자 생성(2,095 / 2,043), 상한 2,800 ✅
- 사진·방문 기록 없이도 경험담을 서술함 ✅ → *설계 원칙 §9 참고*
- 메뉴 이름은 수집된 메뉴 데이터가 있을 때만 구체적으로 나옴(락희옥: 없음 → "메뉴 이름을 적기보다…"로 회피 / 김숙성: 소금구이·삼겹살) 🔶

### 2.3 사진·썸네일
- 사진 0장일 때: 1번 섹션 끝(지도 줄 다음)에 검은 카드(제목 2줄: 첫 줄 노랑, 둘째 줄 흰색) + 그 이미지를 언급하는 문단 ✅. 카드 글씨는 입력한 제목 그대로(오타 포함), 본문 첫 줄은 교정됨 ✅
- 사진 2장일 때: 사진 1은 제목 바로 아래, 사진 2는 인트로 끝, 지도 줄 뒤 이미지 없음(카드도 없음) ✅
- 사진이 해당 내용의 문단 옆에 놓이지 않음(외관 사진은 1번 섹션이 아니라 맨 위) ✅ → 배치 규칙은 **미확정**(업로드 순서 / 사진 종류 / AI 판단) ❓
- 인트로 문장은 사진 내용을 반영해 쓰임 ✅
- 복사본 텍스트의 이미지 자리: 사진 0장(락희옥) → `사진 1`이 지도 줄 다음, 사진 2장(김숙성) → `사진 1` 제목 직후, `사진 2` 인트로 끝. 모두 **단독 줄**이고 번호는 지면 순서(1, 2) ✅. 김숙성은 **외관을 먼저 업로드** → `사진 1`=외관, `사진 2`=불판 ✅. 단, "업로드 순서대로"와 "외관 우선"이 모두 이 결과와 맞아서 아직 구분 불가(Q8)
- 플랜표의 `썸네일 ON/OFF(FREE) / 4종(BASIC)` → 검은 카드가 썸네일의 1종으로 보임 🔶

### 2.4 색연필·서식
- 노란 형광펜+굵게: 두 원고 모두 정확히 2곳 ✅ (고정 규칙으로 보임 🔶)
- 검정 굵게: 검색 키워드 구절, 개수 변동(5곳 / 1곳) ✅
- 색연필 색(빨강·파랑·분홍): 한 원고는 3곳, 다른 원고는 1곳만 사용, 색의 역할도 원고마다 다름 ✅ → "색마다 1번씩"이나 "색=역할" 규칙은 아님. AI가 쓸 때 재량으로 표시하는 구조 🔶
- 색을 바꿔 다시 생성하면 바뀐 색이 반영됨 ✅

### 2.5 복사·붙여넣기 (네이버 에디터 실측)
- 첫 줄이 에디터 제목 칸으로 분리됨(붙여넣기 위치 영향 가능) ✅🔶
- 유지됨: 문단 빈 줄, 굵게, 글자색(빨강·파랑·분홍), 소제목 굵게 ✅
- 사라짐: 노란 형광펜(+그 문장의 굵게), 소제목의 큰 글씨·구분선 ✅
- 이미지는 복사에 포함되지 않고 "사진 N" 자리 표시만 들어간다는 팝업 ✅

### 2.6 해시태그
- 28~29개(네이버 한도 30), 맨 끝 한 줄. 상호, 메뉴·업종, 인근 역/구, 상황(데이트·회식·모임·혼밥), 플랫폼(#네이버맛집), 제목 속 키워드, 매장 리뷰 키워드가 섞임 ✅
- 락희옥은 "마포/공덕 짝 맞춤" 구조, 김숙성은 아님 → 코드 규칙보다 AI 생성에 가까움 🔶

### 2.7 플랜표 요약
| | FREE | BASIC |
|---|---|---|
| AI 모델 | 기본 | 고급 |
| 정보글 본문 사진 | 4장 | 6장 |
| 썸네일 | ON/OFF | 4종 |
| 글 종류 | 정보글 + 맛집/전문직/홍보글(beta) | 전체 |
| 일일/월 한도 | 1 / ~30 | 5 / 150 |
| 플레이스 자동입력, 캐릭터 일러스트 | ✓ | ✓ |

- 지금까지 본 모든 결과는 **FREE(기본 모델)** 것이다. BASIC 결과는 볼 수 없으므로 BASIC은 표 기준 추정 구현. 🔶
- 내 원고의 "14일 보관"은 **사진**에 대한 안내(원고 텍스트 기간은 미표기) ✅

### 2.8 글자수 기준 (락희옥 원고 전문으로 확정, 2026-10-09)
| 카운터 | 값 | 기준 | 표기 |
|---|---|---|---|
| 블덱스 결과 화면 `N / 2800` | 2,095 | **공백 제외 글자 수(한글·숫자·기호 모두), 해시태그 줄은 제외.** 제목·소제목·지도 줄·`사진 1` 줄은 포함. 이 조합에서만 정확히 일치 | ✅ |
| 네이버 에디터 한글 | 2,115 | 본문(제목 칸 제외)의 한글만. 숫자 12도 정확히 일치 | ✅ |
| 네이버 에디터 전체 | 2,973 | 본문 전체, 줄바꿈도 글자로 셈 | ✅ |
| 블덱스 내 원고 목록 `2455자` | 2,455 | 어떤 조합으로도 불일치(공백 제외 전체 2,259 / 공백 포함 2,953) → 원인 미상. 화면 표시용이라 재현하지 않음 | ❓ |

- 김숙성(2,043)도 같은 기준으로 **정확히 일치** ✅. 이 값은 `사진 1`·`사진 2` 줄(6자)을 포함해야 맞음 → 원고 텍스트 안에 이미지 자리가 `사진 N` 줄로 들어 있고, 화면은 이 줄을 이미지로 바꿔 보여주는 구조로 보임 🔶
- 붙여넣은 본문에는 `사진 1` 줄이 없었음(한글 2,115 = 마커 제외 기준) → 복사 결과의 마커를 사용자가 이미지로 대체했을 것 🔶
- 지난 설계의 "한글(가–힣) 기준"은 **틀림**. 한글만 세면 2,000자다.

|---|---|---|---|
| 인트로 | 3 | 2.0 | 267 |
| 1. 위치·분위기 | 4 | 2.8 | 449 |
| 2. 주문한 메뉴 | 4 | 2.8 | 463 |

## 3. 시스템 구조

### 3.1 구성
```
브라우저 (HTML+JS, 빌드 없음)
   │  /api/*
Flask 서버 (blogdex/app.py)
   ├─ places     매장 검색 → 매장 정보(상호·업종·주소·전화·메뉴·리뷰 키워드)
   ├─ photos     업로드 → 축소 저장 → 비전 분석(Claude) → 분석 JSON 저장
   ├─ titles     제목 후보 5개
   ├─ articles   원고 생성 → 검증 → 후처리 → 저장
   └─ storage    SQLite(원고·사진·매장 캐시) + 사진 폴더
Claude API (서버에서만 호출, 키는 .env)
```

### 3.2 기술 선택
- **Flask + SQLite(표준 라이브러리) + 순수 JS**: 기존 저장소(Python)와 맞고 초보자도 읽을 수 있음.
- **로컬 실행 전용**(`127.0.0.1`). 팀 공유가 필요해지면 그때 서버 배포와 로그인을 추가(M6).
- 모델 호출은 서버에서만. 사진은 업로드 시 1280px JPEG로 축소 저장.

### 3.3 생성 파이프라인
1. **매장 정보 수집**(`자동 입력`): 후보 목록 → 사용자가 선택 → 상세 정보 확정 *(데이터 출처는 §11 결정 필요)*
2. **사진 분석**(업로드 직후, 1장씩): 종류(외관/내부/음식/메뉴판/기타), 한 문장 설명, 보이는 글자, 보이는 음식 → JSON 저장
3. **제목 후보**: 입력 키워드 + 매장 정보 → 5개
4. **슬롯 결정(코드)**: 사진 장수와 정책으로 어디에 어떤 사진이 들어갈지 먼저 정함
5. **원고 생성(Claude)**: 구조화 JSON 출력. 슬롯 위치를 프롬프트에 전달해 앞뒤 문장이 사진과 이어지게 함
6. **검증·후처리(코드)**: 태그 검사, 한글 글자수, 해시태그 정리, 지도 줄·사진 슬롯·썸네일 삽입
7. **저장**: 입력 제목, 최종 제목, 본문 JSON, 설정(글꼴·색), 사진 id

## 4. 원고 생성 상세

### 4.1 입력
글 종류, 입력 제목, 매장 정보(맛집글), 사진 분석 JSON 목록과 슬롯 위치, 추가 정보(선택, 메뉴 직접 입력 포함), 선택한 색연필 색 개수(1~4), 티어 설정.

### 4.2 출력 스키마 (JSON 구조화 출력)
```
{ "title": str,
  "intro": [str, ...],                          // 2~3문단
  "sections": [ {"heading": str, "paragraphs": [str, ...]}, ... ],   // 맛집글은 4개
  "hashtags": [str, ...] }                      // 28~30개
```
문단 문자열 안에 인라인 태그를 쓴다.

| 태그 | 의미 | 서버 검증 |
|---|---|---|
| `{{hl}}…{{/hl}}` | 노란 형광펜(화면 전용) | 정확히 2곳 |
| `{{b}}…{{/b}}` | 굵게(검색 키워드 구절) | 1~6곳, 중첩 금지 |
| `{{c1}}…{{/c1}}` ~ `{{c4}}` | 색연필 슬롯 1~4 | 선택한 색 수 이하, 슬롯당 0~1곳, 구절 길이 60자 이하 |

검증 실패(태그 불일치, 개수 위반, 글자수 초과) 시 **1회 자동 재생성**, 그래도 실패하면 태그를 제거하고 텍스트만 저장한다.

### 4.3 맛집글 구조 템플릿
인트로(공감 질문 → 지역 고민 + 첫인상 → 글 소개) → ① 위치·분위기(주소·역 접근, 외관·내부, 좌석·소음·주차 팁, **지도 줄**) → ② 주문한 메뉴 → ③ 다른 메뉴·추천 조합 → ④ 다시 갈 만한가? 소제목은 AI가 문구를 정하되 번호 `N.`을 붙인다.

### 4.4 사진 슬롯 · 배치 정책
- 원고 텍스트에는 이미지 자리를 **단독 줄 `사진 N`** 으로 넣어 저장한다(원본과 동일하게 글자수에 포함). 화면은 이 줄을 사진(또는 썸네일 카드)으로 바꿔 그린다.
- 슬롯: `after_title`, `after_intro`, `end_s1`(지도 줄 다음), `end_s2`, `end_s3`, `end_s4`
- **정책을 교체 가능한 모듈로 분리**한다(`placement.py`). 확인된 관찰만 만족하는 기본값:
  - **front(기본)**: 업로드 순서대로 `after_title → after_intro → end_s1 → end_s2…`
  - **by_category(실험)**: 외관 → after_title, 내부 → end_s1, 음식·메뉴판 → 주문 메뉴 섹션 근처
- 규칙이 §11 테스트로 확정되면 기본 정책만 바꾼다.
- 사진이 0장이고 썸네일 ON이면 썸네일 카드를 `end_s1` 슬롯에 넣는다(원본 관찰과 동일).

### 4.5 썸네일
- 텍스트: **교정된 제목**(원본은 입력 제목 그대로라 오타가 남음 → 우리는 교정본 사용)을 어절 수 기준으로 2줄로 나눔(첫 줄 강조색)
- FREE: 1종(검정 배경 + 노랑/흰 글씨), ON/OFF. BASIC: 4종 선택(나머지 3종은 자체 디자인)
- 이미지는 저장하지 않고 제목+스타일로 화면에서 다시 그린다(복사에는 포함되지 않음).

### 4.6 해시태그
AI가 28~30개 생성 → 코드가 정리(`#` 정규화, 공백·특수문자 제거, 중복 제거, 30개 이내). 상호·지역(구/역) 태그는 누락 시 코드가 추가한다.

### 4.7 글자수
- 화면 카운터 = **공백 제외 글자 수(한글·숫자·기호), 해시태그 줄 제외**(제목·소제목·지도 줄 포함), 상한 2,800 ✅(§2.8)
- 생성 목표: 이 기준으로 약 2,000~2,100자(상한의 약 74%). 상한 초과 시 1회 축약 재생성
- 네이버에서 보이는 한글 수와는 다른 수치임(표시 문구에 기준을 적어 둔다)

### 4.8 복사
- 클립보드에 `text/html` + `text/plain` 둘 다 넣는다.
- HTML에는 `<p>`, `<b>`, `<span style="color:…">`만 사용(네이버 에디터에서 유지되는 것). 형광펜·구분선은 넣지 않음.
- 맨 앞 줄은 제목, 이미지 자리는 `사진 N` 줄. 복사 시 "이미지는 포함되지 않아요" 안내 팝업.

## 5. 화면 설계

**원고 작성**: 글 종류 칩 → (맛집글) 매장 이름 + [자동 입력] + 후보 카드 → 사진 [사진 업로드][폴더로 업로드] + 상태줄 → 제목 + [제목 자동 생성][⟳ R] + 후보 5개 → [원고 생성하기] → 결과.
**결과**: 글자수/사진 수 바, 글꼴·크기·색연필, 본문, [복사 C] [새 원고 N].
**내 원고**: 누적 원고 수, 목록(제목·글 종류·일시), 제목 클릭 → 상세(복사), `×`/선택 삭제, 사진 보관기간 안내.
**원본에서 가져오지 않는 것**: 플랜 안내 배너, 자동발행 안내, 한도 표시, 내 사진 라이브러리, 사진 자동 제외 체크박스.
**디자인**: 원본 화면의 레이아웃·톤을 참고하되 로고·명칭은 쓰지 않고 자체 이름을 사용한다.

## 7. 데이터와 API

**SQLite 테이블**
- `articles`: id, input_title, final_title, kind, tier, created_at, body_json, han_count, colors_json, thumb_style, place_json, photo_ids
- `photos`: id, path, analysis_json, created_at, expires_at(기본 180일)
- `places`: 매장 정보 캐시(같은 매장 재조회 방지)

**보관**: 원고 텍스트는 기한 없음, 사진은 **180일**(`PHOTO_RETENTION_DAYS`로 변경 가능, 3개월~무기한). 만료된 사진은 상세에서 "보관기간 지나 삭제됨"으로 표시.

**API**
| 메서드 | 경로 | 역할 |
|---|---|---|
| GET | /api/places?query= | 매장 후보 검색 |
| POST | /api/places/select | 매장 확정(상세 수집·캐시) |
| POST | /api/photos | 사진 업로드 + 분석 (한 장씩) |
| POST | /api/titles | 제목 후보 5개 |
| POST | /api/articles | 원고 생성·검증·저장 |
| GET | /api/articles, /api/articles/{id} | 목록, 상세 |
| DELETE | /api/articles | 선택 삭제 |

## 9. 원칙과 리스크

1. **경험 서술의 근거 (사용자 결정)**: 원본은 사진·방문 기록 없이도 경험담을 만든다. 후기 형식의 허위 경험은 표시·광고 관점에서 위험하므로 `EVIDENCE_MODE`를 둔다.
   - `strict`: 사진 분석·사용자 메모에 있는 경험만 서술, 그 외는 일반 정보로 작성 (권장)
   - `template`: 원본처럼 자유 서술
2. **홍보글**: 맨 위에 광고·협찬 표기 자리 줄을 넣는다.
3. **지어내기 방지**: 입력에 없는 가격, 수치, 주소, 수상 이력은 쓰지 않거나 `[확인 필요: …]`로 표시한다.
4. **데이터 출처**: 약관상 위험이 있는 비공식 수집은 피하고, 공식 API + 사용자 입력을 기본으로 한다(§11).
5. **보안**: API 키는 서버에만, 서버는 `127.0.0.1`에만 연다. 업로드 크기·형식·장수 검증.
6. **개인정보**: 사진은 분석을 위해 Claude API로 전송된다. 얼굴·차량 번호판이 나오는 사진은 주의.
7. **명칭·로고**: 원본의 이름·로고·문구를 쓰지 않는다.

## 10. 구현 단계

| 단계 | 내용 | 완료 기준 |
|---|---|---|
| M0 | 기존 초안 정리, 폴더 구조·DB·설정(`TIER`) 마련 | 서버 기동, 설정으로 티어 전환 |
| M1 | 구조화 생성(맛집글) + 검증 + 결과 화면(글꼴·크기·색연필) + 복사 HTML + 내 원고 | 네이버 에디터 붙여넣기에서 굵게·색·문단 유지 |
| M2 | 사진 업로드·분석·슬롯 배치·썸네일 | 사진 0/2/4장 결과가 §2.3 관찰과 동일한 형태 |
| M3 | 매장 정보 확장(메뉴·리뷰 키워드) | 메뉴·키워드가 제목·본문·해시태그에 반영 |
| M4 | 정보글·전문직·홍보글·기타 | 글 종류별 구조가 원본 샘플과 유사 *(정보글 샘플 필요)* |
| M5 | BASIC 설정 적용 | 모델·사진 6장·썸네일 4종 전환 확인 |
| M6 | (선택) 팀 공유: 서버 배포, 로그인 | 필요 시 별도 설계 |

각 단계 끝에 사용자가 원본과 같은 입력으로 비교해 보는 확인을 한다.
